Humans and agents, one sessionunder your control

Not an IDE with AI bolted on. A workspace you and your agent share.

You and your agent work on the same computational context. No copying code from a chat into a console, no re-running an agent's script to get its objects back, no switching windows: the agent works in the session you are looking at, and you decide what it may do. Corral is the harness in between: a few commands the agent calls, a skill that teaches them, and rules it can't skip (how it works). Built for the flow of data science as it is done today, and out of your way.

The agent proposes. You decide.

Every time your agent runs code, it goes through corral eval: the code is typed into the console you are looking at, and its objects, tables and plots stay there for both of you to inspect and build on. Corral Harness is the set of rules around each request that makes this joint work safe, enforced in Corral's own code, whatever the model was told.

Built on herdrand more than herdr

herdr runs the panes. Corral turns them into a workbench.

herdr is the terminal multiplexer Corral runs on: workspaces, tabs and panes that keep running when you close the window, with your agents in them. Corral doesn't stop there. It builds on herdr and takes it further, into a full data science workspace:

  • A live sessionR on Ark or Python in IPython, shared with your agent
  • Viewsthe variables, tables through DuckDB and plots over your panes; Mirador in the browser
  • The harnessrules around every agent request, enforced in Corral's own code
  • One paletteevery Corral and herdr action under ctrl+b space

Rust, end to end.

The engines it drives are Rust too: herdr, Fresh, Ark, Air, Ruff, ty and uv. That's why a whole workspace, editor and language server included, is ready in about 400 milliseconds.

03

Big tables, instantly. DuckDB under the hood.

View(df) saves the table as Parquet, and Corral asks DuckDB only for what's on screen: a page of rows, the count, a sort, a search, a filter in R or SQL, a summary of every column. Each takes milliseconds. With ten million rows, saving the table takes about a second with nanoparquet; from then on each screen takes about 15 ms. The viewer uses about 3 MB, and DuckDB about 35 MB while the table is open; it closes when you stop. Press m to send the table to Mirador when you want the browser, and the variables pane keeps every object in view as you work.

Close the terminal, lose nothing. Not even in a crash.

Corral lives in herdr TUI, herdr's terminal workspace: close the window and your consoles keep running, with the workspace exactly where you left it. If R or Python crashes, your objects come back by themselves about a second later: the tables, the models, the functions you wrote and the packages you loaded. Corral keeps them from the background, so the prompt doesn't feel it, measured over a thousand commands.

Why Corralthe idea

A corral for the herd.

Corral runs on herdr, and a herd needs a corral: one place where you gather the consoles, the editor, the data, the plots and your agent, and work with them under rules you set. Behind it is one idea: in data science the work happens in a live session, so the agent should work there too, where you can see it.

  • The sessionthe agent works in your live session, not in a script you run again to get its objects back
  • A harnessno chat and no model of its own: the agent you already use, with rules around it
  • Seen, approvedevery request is typed in your console, and by default waits for your approval
  • Lightmade for a day's work: it opens in milliseconds and stays steady until evening
  • Where it fitsexploring, iterating with the agent, validating, and checking models already in use (performance, bias, drift); your repository, tests and pipelines keep the rest

FAQquestions

Questions people ask.

Which agents does it work with?

Any agent that can run shell commands: Claude Code, Codex, Gemini CLI, opencode and others. They run code in your console with corral eval, and Corral's skill follows the open Agent Skills standard, so the installer puts it where they look for it (~/.agents/skills, and ~/.claude/skills for Claude Code).

Does it replace Positron, RStudio or VS Code?

No. Positron, RStudio, VS Code and its forks (Cursor, Windsurf…) are still the right tools for heavier work, and Corral doesn't touch them. Corral is for working with agents on your data without losing control of the data or the code: the agent runs its code in your console, where you watch every line, and what it creates stays in your session, in plain sight.

None of them has to be installed: Corral runs R on Ark, the kernel Positron uses, on its own, and the installer downloads it.

Is Python as complete as R?

Both get the whole workbench: the editor, the console, the variables pane, View(), plots in Mirador and agents. R is the default console, and its language server knows your live objects. Python runs in IPython inside your project's uv environment, with ty and Ruff in the editor.

How big can my data be?

Looking at it scales: View() saves the table as Parquet and DuckDB reads only what's on screen, so ten million rows take about a second to open with nanoparquet, and then about 15 ms a screen. Computing is up to your code, as in any IDE: data frames live in memory, while arrow, duckdb, polars or data.table let you go further.

Does it run on macOS or Windows?

On Linux, and on Windows through WSL. Setting up WSL takes about ten minutes and no Linux knowledge: step by step. The macOS version is in development; until it is out, Corral doesn't run on a Mac.

Does my data leave my machine?

Your data and code never leave it: Corral runs everything locally, and Mirador listens only on 127.0.0.1, behind a token. Your agent talks to its own provider as it always does. The one thing Corral sends is an anonymous ping when an installation finishes (version, system and country, no IP), to count installs; CORRAL_NO_TELEMETRY=1 turns it off (details).

Can I use it with sensitive data?

Corral gives you the controls, and tells you plainly what they cover. You can require your approval for every request an agent makes (corral config agents ask), review each result before the agent sees it (agent_output review) or let it see only the shape of results, without their values (agent_output structure, together with ask, since the agent writes the code), mark a single session as sensitive (corral_sensitive()), and review everything with corral audit. What the agent reads still goes to its model provider, so for data such as health records pair this with a local model or an approved provider, and with the agent's own permissions. The Security model has the details and a checklist.

Can I use it in Spanish?

Yes. Corral speaks English by default; corral config language es, or "Idioma: español" in the palette, switches its windows, messages and Mirador to Spanish. Commands stay in English.

How do I remove it?

corral uninstall takes out everything the installer added, from herdr, R, the editor and your agents. The copies of the files it changed stay, in case you want them.
