Humans and agents, one sessionunder your control

Not an IDE with AI bolted on. A workspace you and your agent share.

You and your agent work on the same computational context. No copying code from a chat into a console, no re-running an agent's script to get its objects back, no switching windows: the agent works in the session you are looking at, and you decide what it may do. Corral is the harness in between: a few commands the agent calls, a skill that teaches them, and rules for every request it makes through Corral (how it works). Built for the flow of data science as it is done today, and out of your way.

The agent proposes. You decide.

When your agent runs code in your session, it goes through corral eval: the code is typed into the console you are looking at, and its objects, tables and plots stay there for both of you to inspect and build on. Corral Harness is the set of rules around each request that makes this joint work safe, enforced in Corral's own code, whatever the model was told. Commands an agent runs with its own tools, outside Corral, are up to its own permissions.

Securityfor sensitive data

Built for data you have to protect.

Data science runs on records about people: patients, clients, students. Corral treats protecting them as part of the work. It decides how much of each result reaches your agent's model, keeps your sessions closed to everyone else on the machine, deletes its copies of your data when you ask, and writes down where its protection ends.

  • Values stay outin a sensitive project the agent learns whether the code worked and the shape of your objects, not their values, and each request waits for you to read its code, since an error's first line could still carry one; your plots stay with you
  • Closed to otherson a shared server, other users can't read your sessions: R talks to Corral over sockets in a folder only you can open, and every local server asks for a token
  • Copies deletedturn checkpoints off and the copies of your objects are deleted, not just no longer made: at once for consoles that have ended, at its next command for one still open
  • Verified installeverything the installer downloads is checked by SHA-256 before it is used, Corral's package also by its build provenance; no sudo; Corral itself has no third-party Rust dependencies
  • Honest limitsa threat model that says what Corral protects, from whom, and what stays with your agent's permissions, its model provider and your machine

Your work survivescheckpoints

A crash doesn't take your work with it.

herdr keeps the panes and your agent running when you close the window. Corral keeps what you built in the session: as you work, it saves a checkpoint of your objects, without the prompt feeling it, and puts them back when R or Python start again. The tables, the models, the functions you wrote, the packages you loaded, and the plots you drew: the newest 30 come back first in Mirador.

  • Window closedeverything keeps running: R, Python, the agent and Mirador (herdr)
  • LSP dropsnothing is lost: the editor's language server only talks to R, which keeps its objects; completion comes back when the editor restarts it
  • R crashesa new session about a second later, with your objects and plots back, and why it ended (out of memory, a package, stopped from outside); Python's come back the next time you run it (Corral)
  • Server stopswsl --shutdown or a Windows restart: herdr brings the panes back, and Corral the objects and plots, in the next console of the project

What can't come back: connections to a database or a file, objects over 1 GB (you can raise it), and an R plot too heavy to keep, a scatter of more than about 200,000 points; kept in a variable, it comes back as an object and draws again.

Big tables, instantly. DuckDB under the hood.

View(df) saves the table as Parquet, and Corral asks DuckDB only for what's on screen: a page of rows, the count, a sort, a search, a filter in R or SQL, a summary of every column. Each takes milliseconds. With ten million rows, saving the table takes about a second with nanoparquet; from then on each screen takes about 15 ms. The viewer uses about 3 MB, and DuckDB about 35 MB while the table is open; it closes when you stop. Press m to send the table to Mirador when you want the browser, and the variables pane keeps every object in view as you work.

Why Corralthe idea

A corral for the herd.

Corral runs on herdr, and a herd needs a corral: one place where you gather the consoles, the editor, the data, the plots and your agent, and work with them under rules you set. Behind it is one idea: in data science the work happens in a live session, so the agent should work there too, where you can see it.

  • The sessionthe agent works in your live session, not in a script you run again to get its objects back
  • A harnessno chat and no model of its own: the agent you already use, with rules around it
  • Seen, approvedevery request is typed in your console, and by default waits for your approval
  • Lightmade for a day's work: it opens in milliseconds and stays steady until evening
  • Where it fitsexploring, iterating with the agent, validating, and checking models already in use (performance, bias, drift); your repository, tests and pipelines keep the rest

FAQquestions

Questions people ask.

Which agents does it work with?

Any agent that can run shell commands: Claude Code, Codex, Gemini CLI, opencode and others. They run code in your console with corral eval, and Corral's skill follows the open Agent Skills standard, so the installer puts it where they look for it (~/.agents/skills, ~/.claude/skills for Claude Code and ~/.gemini/skills for Gemini CLI).

Does it replace Positron, RStudio or VS Code?

No. Positron, RStudio, VS Code and its forks (Cursor, Windsurf…) are still the right tools for heavier work, and Corral doesn't touch them. Corral is for working with agents on your data without losing control of the data or the code: the agent runs its code in your console, where you watch every line, and what it creates stays in your session, in plain sight.

None of them has to be installed: Corral runs R on Ark, the kernel Positron uses, on its own, and the installer downloads it.

Is Python as complete as R?

Both get the whole workbench: the editor, the console, the variables pane, View(), plots in Mirador and agents. R is the default console, and its language server knows your live objects. Python runs in IPython inside your project's uv environment, with ty and Ruff in the editor.

How big can my data be?

Looking at it scales: View() saves the table as Parquet and DuckDB reads only what's on screen, so ten million rows take about a second to open with nanoparquet, and then about 15 ms a screen. Computing is up to your code, as in any IDE: data frames live in memory, while arrow, duckdb, polars or data.table let you go further.

Does it run on macOS or Windows?

On Linux, and on Windows through WSL. Setting up WSL takes about ten minutes and no Linux knowledge: step by step. The macOS version, for Apple silicon and Intel, is almost here: Corral already runs and installs on a Mac in the project's tests, and it comes in an upcoming version, with the same install line.

Does my data leave my machine?

Corral runs everything locally: your sessions, files and data stay on your machine, and Mirador listens only on 127.0.0.1, behind a token. Code that runs in your console, yours or an agent's you let through, has your user's permissions and can use the network like any R or Python: Corral isn't a sandbox, and its output controls only limit what goes back to the agent. What your agent reads (results, errors, plots, previews of variables, the script draft) goes to its model provider, under that provider's terms. Corral decides what comes back through its harness (review, results without values, sensitive projects); what the agent reads with its own tools is up to its own permissions. For sensitive data, use a local or approved model and limit the agent's permissions (setup). Corral itself sends two things. The installer sends an anonymous ping when it installs, updates, stops or uninstalls (version, system, country and coarse categories such as the agent and herdr's version, no IP); corral config telemetry off or CORRAL_NO_TELEMETRY=1 turns it off (details). And once a day, opening the workspace asks GitHub which version is the latest, which carries nothing about you; corral config update_check off stops it.

Can I use it with sensitive data?

Corral gives you the controls, and tells you plainly what they cover. You can require your approval for every request an agent makes (corral config agents ask), review each result before the agent sees it (agent_output review) or let it see only the shape of results, without their values (agent_output structure, together with ask, since the agent writes the code), set all of that in one step with a profile, for all your work or for one project folder (corral profile sensitive --project: every session there asks and gets no values, and the stricter profile wins), mark a single session as sensitive (corral_sensitive()), and review everything with corral audit. What the agent reads still goes to its model provider, so for data such as health records pair this with a local model or an approved provider, and with the agent's own permissions. On a shared server, other users can't read your sessions, and turning checkpoints off deletes the copies of your objects. The Security model has the details and a checklist; the Threat model says what each control holds against.

Can I use it in Spanish?

Yes. Corral speaks English by default; corral config language es, or "Idioma: español" in the palette, switches its windows, messages and Mirador to Spanish. Commands stay in English.

How do I remove it?

corral uninstall takes out everything the installer added, from herdr, R, the editor and your agents. The copies of the files it changed stay, in case you want them.
