Install

Before you start you need a Linux system (or Windows with WSL), herdr, and R with two packages. The installer brings everything else, and it checks all of it before it changes anything: if something is missing, it tells you what to run and stops.

On Windows: set up WSL first

Corral runs on Linux. On Windows it runs inside WSL (Windows Subsystem for Linux), which gives you a real Ubuntu next to Windows, with no virtual machine to manage. You set it up once, in about ten minutes, and you don't need to know Linux for it: copy each command, paste it, and press Enter. On Linux, skip to Before you install.

  1. Check your Windows. You need Windows 11, or Windows 10 version 2004 or later. To see yours, press Win+R, type winver and press Enter.

  2. Install WSL with Ubuntu. In the Start menu, type PowerShell, right-click it and choose Run as administrator. Paste this and press Enter:

    PS> wsl --install

    It turns on WSL 2 and installs Ubuntu. Restart the computer when it finishes.

  3. Create your Linux user. After the restart, open Ubuntu from the Start menu. The first time, it asks for a username and a password for Linux; they don't have to match your Windows ones. While you type the password, nothing appears on the screen: that's normal, keep typing and press Enter. Keep it: Ubuntu asks for it when a command starts with sudo.

  4. Bring Ubuntu up to date. In the Ubuntu window:

    $ sudo apt update && sudo apt upgrade -y

  5. Install R with rig. rig installs R in your home folder and sets up ready-built packages, so nothing has to be compiled:

    $ curl -LsSf https://r-lib.github.io/rig/install.sh | sh
$ rig add release

    Close Ubuntu and open it again, so it finds R. Then add the two packages Corral needs:

    $ Rscript -e 'install.packages(c("httpgd", "jsonlite"))'

  6. Install herdr, the terminal workspace Corral lives in:

    $ curl -fsSL https://herdr.dev/install.sh | sh

  7. Install Corral with the line in Install with one line. It checks everything first and tells you if anything is still missing, with the command to fix it.

Working in WSL

  • Where to open it. Ubuntu is in the Start menu. Windows Terminal (it comes with Windows 11; on Windows 10, get it from the Microsoft Store) opens it in a tab: choose Ubuntu from the menu next to the tabs. Then type herdr and press Enter.
  • Keep your projects in Ubuntu. Work in your Linux home folder, ~ (for example ~/projects/sales), not under /mnt/c/…, where your Windows C: drive shows up: Microsoft recommends it because it's much faster. explorer.exe . opens the folder you're in in Windows' File Explorer, and \\wsl$ in its address bar shows all of Ubuntu's files.
  • Your Windows browser does the rest. Mirador and R's help pages open in it.

Install with one line

$ curl -LsSf https://corral-term.dev/install.sh | sh

The installer speaks English. To read it in Spanish, set CORRAL_LANG=es; an update already speaks the language you chose with corral config language.

$ curl -LsSf https://corral-term.dev/install.sh | CORRAL_LANG=es sh

First it prints a checklist of everything above: what you have (✓), what is missing (✗), what it will download (↓) and what is optional (!). Under each missing item it shows the command that fixes it. If anything required is missing, it changes nothing and stops: fix those and run the same line again. How the download is checked

  • It installs a published version, the latest unless you pick one with CORRAL_VERSION=v0.1.3, and says which. It never falls back to unreleased code: if the download fails, it stops and says why.
  • Before opening the package it checks its SHA-256 against the one published with that version, and stops if they differ. That catches a download that arrived broken or changed on the way. Both files come from the same release, though, so someone able to publish there could replace both.
  • The attestation covers that case. Each package carries a build provenance attestation, signed by GitHub when the project's workflow builds it, which proves the package came from that workflow and that version's code. If you have the GitHub CLI (gh 2.49 or later, logged in), the installer checks it and stops if it doesn't hold; without it, it says the attestation wasn't checked. You can also check it yourself: 
    $ gh attestation verify corral-term-x86_64-linux.tar.gz --repo paulovillarroel/corral-term
  • Fresh, DuckDB, Air and Ark, which it downloads when you don't have them, are each checked against a SHA-256 written into Corral's own code for the version it installs, so the check doesn't depend on their projects publishing one. A version of Ark you choose yourself (corral ark --install 0.1.250) is checked against the SHA-256 GitHub reports for it, and refused if there is none.
  • The script runs from a single function called on its last line, so a download cut halfway runs nothing.

It never uses sudo and only writes inside your home folder. It also checks that ~/.local/bin is on your PATH, since R and the editor look for corral there; if it isn't, add this line at the end of ~/.bashrc (or ~/.zshrc) and open a new terminal:

export PATH="$HOME/.local/bin:$PATH"

When it finishes, open herdr in a project folder and press ctrl+b a. The quick start takes it from there.

What changes on your machine

Before it touches a file of yours, the installer saves a copy next to it, named *.before-corral-DATE.

  • Corral goes in ~/.local/share/corral-term, and the command in ~/.local/bin/corral. To use another folder, set CORRAL_DIR=/other/folder before you install.
  • herdr: it links Corral's plugin and adds its shortcuts at the end of ~/.config/herdr/config.toml, between two Corral comments. If you already use one of those keys, it leaves yours and tells you; corral keys --change gives the Corral action another key (see Keyboard shortcuts).
  • R: one line in ~/.Rprofile that loads Corral. It only switches on in the consoles Corral opens; your other R sessions don't change.
  • Fresh: it adds Corral's shortcuts and language servers to ~/.config/fresh/config.json without removing your settings, and links its plugin.
  • Agents: it links Corral's skill in ~/.agents/skills/corral-r, the shared folder of the open Agent Skills standard, which Codex and other agents read, and in ~/.claude/skills/corral-r if you have Claude Code. If you already have a folder of your own with that name, it leaves it alone.

The line in ~/.Rprofile looks like this, with the full path to your copy of Corral:

if (interactive()) try(source("~/.local/share/corral-term/r/corral.R"))  # Corral

Anonymous install count

When an installation finishes, the installer sends one anonymous ping to corral-term.dev, so the project knows how many people install Corral and from which countries. The ping says only:

  • the version of Corral (0.1.14);
  • the system: Linux or WSL;
  • whether it is a new install or an update;
  • whether it came from the published package or a clone.

The country comes from the request itself, through Vercel's geolocation; the IP address is never stored. No names, paths, hostnames or anything about your data or code. The code that receives it is api/installed.js. Checking (--check) sends nothing.

To install without it, set CORRAL_NO_TELEMETRY=1 (DO_NOT_TRACK=1 works too):

$ curl -LsSf https://corral-term.dev/install.sh | CORRAL_NO_TELEMETRY=1 sh

Check without installing

To see the checklist without changing anything, add --check:

$ curl -LsSf https://corral-term.dev/install.sh | sh -s -- --check

Once Corral is installed, corral install --check does the same.

Install from a clone

From a copy of the repository, the installer uses that copy where it is, without downloading Corral. It's the way to work on Corral itself, or to try something that isn't published yet.

$ git clone https://github.com/paulovillarroel/corral-term.git
$ sh corral-term/install.sh

If the copy has no compiled corral, the installer builds it with cargo. When you change something in rs/, build it again with cargo build --release; corral --version tells you which folder the binary you are using comes from.

Tests

$ cargo test --manifest-path rs/Cargo.toml
$ cargo test --release --manifest-path rs/Cargo.toml --test live -- --ignored --test-threads 1

The first runs the unit tests (the JSON, TOML and zip readers, the ZMTP and Jupyter protocol Corral speaks to Ark, the audit log's dates) and checks Mirador's API: without its token, or from another address, it answers 403. GitHub runs them on every pull request.

The second runs the live tests. Each starts its own herdr server with an R console, and Python when the test needs it, and checks what agents rely on, in both languages: two agents asking at once take turns, a timeout leaves the code running and keeps its output, Ctrl+C stops it and keeps the session, a crash is reported at once and the next request gets a new session, and the variables are never read half-written. For R they also check that a crashed R comes back by itself and that the editor's language server reaches Ark; for both, that the objects come back after a crash, and that closing on purpose starts clean. checkpoints_cost_report, python_checkpoints_cost_report and restore_time_report print the measurements in Performance. They need herdr, R, Ark and uv, and leave your herdr, sessions and settings alone; their panes run /bin/sh, so they use the corral being tested even when your .bashrc puts another one first.

Update

$ corral update

It finds the latest published version and, if it is newer than yours, runs the same install line as the first time, which you can also run yourself. That replaces your copy of Corral and doesn't repeat what is already done: in herdr's configuration, for example, it only adds shortcuts that are new. corral update --check only says whether there is a newer version, and the palette has "Update: install the latest version of Corral". Consoles already open keep the version they started with; the next ones you open use the new one.

If you installed Corral from a copy of the repository, update that copy: git pull in it, then sh install.sh, which builds the new version.

corral install checks and repairs the installation from the copy you have, without downloading Corral again, and corral install --check only checks.

Uninstall

$ corral uninstall

corral uninstall removes the herdr plugin and shortcuts, the line in ~/.Rprofile, Corral's shortcuts, theme and language servers in the editor (and gives you back your own shortcuts it had replaced), the skill, the programs it downloaded and its copy of Corral. It saves a copy of each file it changes, and it never deletes a cloned copy of the repository.

Your settings and sessions stay in ~/.config/corral and ~/.local/state/corral, in case you come back. Delete them if you won't.

Publish a version

The installer downloads the package of the latest version published on GitHub. That package includes corral already compiled, so nobody needs Rust. The action .github/workflows/version.yml builds it when you push a tag that starts with v, and publishes it with its SHA-256 and a build provenance attestation. First put the new number in rs/Cargo.toml and herdr/herdr-plugin.toml, so corral --version, the herdr plugin and Mirador say the same, and write its section in CHANGELOG.md (## 0.1.15): it becomes the release notes, and without it nothing is published. Run the live tests too, which check Corral with a real herdr, R and Python: in GitHub, Actions → Live tests → Run workflow, or on your machine cargo test --release --test live -- --ignored --test-threads 1. Then tag it with that number:

$ git tag v0.1.15
$ git push origin v0.1.15

The binary is static (musl), so it runs on any x86_64 Linux, WSL included.

The package appears on the release a few minutes after the tag, when the workflow finishes; until then the installer keeps installing the previous version. A version without its package or its SHA-256 doesn't install: the installer stops and says so, and never builds from main instead.

When Fresh, DuckDB, Air or Ark move to a new version, its SHA-256 changes too: put it next to the version in rs/src/install.rs (rs/src/setup.rs for Ark). GitHub shows it on the release page, and this prints it:

$ gh api repos/posit-dev/air/releases/tags/0.13.0 --jq '.assets[] | .name + "  " + .digest'

macOS

The macOS version is in development; until it is out, Corral doesn't work on a Mac. herdr runs on a Mac, but some pieces of Corral use features only Linux has. Known limits lists them.
