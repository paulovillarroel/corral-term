Working with agents

Agents run code in your console with corral eval, so their objects, plots and tables land in the session you are looking at. Any agent that can run shell commands learns how from Corral's skill.

Your agent

The layout opens your agent in its agent pane: the first one installed of Claude Code, Codex, Gemini CLI and opencode. To choose another, or none and a shell in its place, use the palette (ctrl+b space, "Agents: use … in the agent pane") or corral config agent, which takes any command; the next layout you open runs it. The installer says which agent it found and, when you have several and haven't chosen, asks you once which one to open.

The agent harness

Corral is the harness between your agent and your live session: a few commands the agent calls from its own shell, a skill that teaches it when and how to call them, and rules that Corral enforces around every call. The agent gets no hidden channel into your session. Everything it runs is typed into the console you are looking at, it waits its turn, and what it gets back depends on what you allow.

What always holds

  • In plain sight. Code is typed into your console after a # corral eval line; nothing runs in a hidden process. Characters that would hide part of it, control or invisible ones, are written out, there and in the approval popup.
  • One at a time. Requests to a console queue; several agents never interleave.
  • Bounded. The agent stops waiting after a time limit (the code keeps running in your console), and the output is clipped before it reaches the agent.
  • Yours to decide. agents ask (the default), on or off; full results, your review first, or structure only; one session marked sensitive. All in the palette, and enforced in Corral's own code, whatever the model was told.
  • Recorded. Every request lands in the local audit log: corral audit.
  • Any agent. Claude Code, Codex, Gemini CLI, opencode or another: the harness is shell commands plus a skill in the open Agent Skills format.

The harness is not a sandbox: an agent with an unrestricted shell can do things outside it. The Security model explains how to close that gap with the agent's own permissions.

corral eval

corral eval runs code in your console and prints what it printed. R is the default; --lang python runs Python, and starts the Python console if it isn't there yet. You see each command appear in the console after a # corral eval line, and the objects, plots and tables stay in your session.

It works from any terminal or script, too:

$ corral eval 'summary(mtcars)'
$ corral eval --file analysis.R
$ corral eval --lang python 'df.describe()'
$ corral eval --lang sql 'SELECT region, count(*) FROM sales GROUP BY 1'
$ corral vars --json

It also reads the code from stdin. If the console isn't there, isn't in view, or was quit, corral eval brings it into view or starts it first.

What comes back

The code, echoed (> in R, >>> in Python), followed by what it printed. In R every top-level value prints, messages included, and warnings come after the output as [corral] warning: .... In Python, as in IPython, only the value of the last expression prints.

Output longer than 20,000 characters is cut in the middle, and the path to the full text is printed. --max-chars changes that limit.

Exit codeMeaning
0It ran without errors.
1Error. The message is the last line; statements before the failing one already ran.
2The console was still busy after --wait-idle, it had a half-typed line, or --timeout ran out (the code may still be running).
3Nothing ran: agents can't run code (agents off), you refused the request, or it couldn't be approved (no answer within 5 minutes).

Plots

Each new plot is saved as a PNG and reported as [corral] plot N saved to <path>, numbered as you see it in Mirador. That way the agent can look at what it drew.

An agent that reads images looks at each plot it draws, and sometimes fixes it: it moves labels or changes a scale. So that you don't end up with near-identical versions in Mirador, the fix goes with corral eval --replace, and the new plot replaces the ones from the previous request. If you ask for a different plot, or want to compare versions, it is added to the history as usual.

Waiting and taking turns

If the console is busy, corral eval waits up to 20 seconds (--wait-idle). If you have a half-typed line, it runs nothing and says so. Several agents can use the same console: their requests run one at a time.

--timeout (300 seconds by default) is how long it waits for the result. After that, it exits with code 2 and the code may still be running. A request the console only reaches after its agent gave up doesn't run at all.

What the agent knows before it runs anything

$ corral context --json

One call tells the agent where it is and what it may do, so it doesn't learn it by being refused. For each console, R and Python: whether it runs, its session, version and folder, whether it is the one in view, and whether SQL works there (R needs the duckdb and DBI packages). Then the rules you set, as they apply to that session: access (on, ask or off) and output (full, review or structure); a session marked with corral_sensitive() always asks and never gives full output. agents holds the rules for a console that hasn't started. It reads files Corral already writes and herdr's list of panes: it starts no console, Python included, and takes about 2 ms.

{"corral":"0.2.0","herdr":true,"workspace":"w1","showing":"r",
 "consoles":{"r":{"running":true,"pane":"w1:p3","session":"w1-p3-162502","version":"4.6.1","cwd":"~/proj",
                  "showing":true,"sql":true,"sensitive":false,"access":"ask","output":"full"},
             "python":{"running":false,"starts_on_request":true}},
 "agents":{"access":"ask","output":"full"}}

The agent can read the rules, not change them. To see exactly what it sees, open the palette (ctrl+b space) and pick "Agents: what your agent sees": a window shows the same in words. corral context without --json prints it in a terminal.

Check one console

$ corral eval --check
$ corral eval --check --lang python

With a console, it prints the console and its session as JSON: the pane, the language, the session, the R or Python version, the folder, and active, which says whether that console is the one in view.

Corral's skill

Corral's skill, skills/corral in Corral's folder, follows the open Agent Skills standard. The installer links it into ~/.agents/skills/corral, where Codex, opencode and other agents look for skills, into ~/.claude/skills/corral for Claude Code, and into ~/.gemini/skills/corral for Gemini CLI. With it, your agent runs its code in your console instead of opening an R or a Python of its own. It switches on when the agent works inside herdr and a Corral layout exists.

It is text only: Markdown your agent reads, and nothing that runs when it loads the skill. Agent Skills can carry commands that run as a skill loads, before the model reads it and without a permission prompt (in Claude Code, a ! followed by a command in backquotes), and scripts of their own; Corral's has neither, and a test in rs/tests/skill.rs fails the build if it ever does. Everything your agent does with Corral, it does by running corral commands it can see, through its own permissions and the harness.

What it does

  • It checks first, with corral context --json: which consoles run, whether SQL works, and the rules you set, so with ask it puts related code in one request and with restricted output it works from shapes. If there is no R console, or Corral isn't active in it, it tells you that ctrl+b a opens one and ctrl+b m switches Corral on in an R you already have. For Python, no console yet is normal: its first request starts one.
  • It looks before it runs, with corral vars --json, so it uses your object names and doesn't overwrite your objects.
  • It runs code with corral eval and reads the PNG of each plot before it describes or adjusts the plot. It uses --replace only to fix a plot its own previous request drew.
  • It keeps the output small (head(), str(), summary(), df.head()), and does scratch work in local({ ... }) in R, or in a function in Python, so your environment stays clean.
  • To show you a table, it runs View(df) through corral eval, and the table opens in your viewer.
  • When you ask, it rearranges the panes (corral toggle, corral switch), and reads or changes your shortcuts (corral keys).
  • It answers questions about Corral from these pages, which come with Corral, and from corral --help, and reads your settings with corral config. It changes a setting only when you ask, and never agents or agent_output: for those it gives you the command or the palette entry, so the change comes from you.

What it asks before doing

  • Anything destructive or global: rm(list = ls()), q(), setwd() or os.chdir(), resetting options(), installing or removing packages (uv add changes your project), overwriting an object you created, writing files outside the project.
  • Changes to what you see: adding the editor (corral script), opening the variables window, opening a new layout and, always, closing Corral (corral close).
  • Replacing your draft, or saving it. It never saves the draft on its own initiative.
  • Taking a key from another shortcut (--force).
  • Using Rscript or a separate Python when your console isn't available.

It never types keys into your console. If the console has a half-typed line, it asks you to finish or clear it.

These are instructions for the agent. What Corral enforces whatever the agent decides (approving every request, restricted output, sensitive sessions, the audit log) is in the Security model.

It still uses Rscript or a separate Python for package checks (devtools::test(), R CMD check, pytest), and for work you want kept apart from your session.

Agents in your draft

$ corral script --read
$ echo 'model <- lm(mpg ~ wt, data = cars_df)' | corral script --write
$ corral script --save analysis/model.R

They act on the draft of the console in view: draft.R or draft.py in a session that uses both. --read prints the draft, unsaved edits included. --write adds text at the end, as one edit you can undo with Ctrl+Z; with --replace it replaces everything. --save writes the draft into your project, and refuses to replace a file unless you add --force. The script editor has the details.

Without a Corral console

Your agent uses your console only if the workspace has an active Corral console. Otherwise, it works as usual. If it opens its own R instead of using yours, corral eval --check should answer with your console; if it doesn't, switch Corral on in that R with ctrl+b m.
