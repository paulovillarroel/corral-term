Consoles: R and Python

The console spot holds R or Python. R runs on Ark, Positron's R kernel, or on plain R if you prefer. Python runs in IPython inside your project's uv environment.

R on Ark

When Ark is installed, the R console is Ark. Corral starts it and talks to it directly over the Jupyter protocol, with its own console written in Rust (3 MB). This is how it behaves:

  • The prompt is In [1]:, and ...: on the lines that follow. Code from Ctrl+R arrives as one pasted block and shows complete at the prompt.
  • Enter runs the code when the expression is complete. If a parenthesis or a brace is still open, it moves to the next line, indented. Alt+Enter runs it anyway.
  • ↑ ↓ go through the history; if you already typed something, only the entries that start the same. The history is saved in ~/.local/state/corral/history-r.jsonl.
  • Tab completes with R's own completion: functions, arguments, columns after $, packages.
  • Ctrl+C interrupts what is running, or clears what you typed. Ctrl+D on an empty line closes the console, like q(). Ctrl+A, Ctrl+E, Ctrl+K, Ctrl+U, Ctrl+W and Ctrl+L work too.
  • readline() and menu() ask their questions in the console, as in R.
  • ?mean or help(mean) open the help in a browser window.
  • Variables, plots in Mirador, View(), corral eval and the rest of Corral work the same as with plain R. Ark points some R options (the graphics device, the browser, the editor) at Positron's panes, which don't exist here; Corral's R file protects them with ark.protected_options so they stay Corral's.

Why Ark

The gain is in the editor and in resources. Completion comes from the console's own R, so you don't need a second R for the language server. Measured with the same packages loaded (dplyr and ggplot2) and one plot, Ark takes about 330 MB with its language server included, plus about 6 MB for the console and the bridge. Plain R takes about 250 MB, plus about 450 MB for languageserver. At rest, Ark uses 0.1 % CPU and languageserver 3 %.

Install or update Ark

$ corral ark
$ corral ark --install

corral ark shows what is installed and whether the R console uses Ark. --install downloads Ark into ~/.local/share/corral/ark; without a version it installs 0.1.252, the one Corral was tested with. You can name another version (corral ark --install 0.1.252), and Corral uses the newest one installed.

Ark is still a 0.1 version, and Corral talks to its language server over an internal Positron channel (positron.lsp) that can change between versions. That is why corral ark --install installs the tested version. If a new version fails, corral config r_console r goes back to plain R.

Plain R

$ corral config r_console r
$ corral config r_console ark

The first goes back to plain R, the second to Ark. The change applies to the consoles you open afterwards. Without Ark installed, the console is plain R anyway. r_console also takes a command of your own.

Ark with jupyter-console

To use Ark through jupyter-console instead of Corral's console:

$ corral config ark_frontend jupyter
$ corral config ark_frontend corral

The second goes back to Corral's console. Corral writes its own kernel definition for Ark, so your Jupyter setup stays as it is. corral doctor tells you if jupyter-console is missing (uv tool install jupyter-console installs it).

Python in IPython

R is the default console. To start with Python instead, choose "Layout: start with Python" in the palette (corral config start python): new layouts open the Python console and a draft.py. In a project with R and Python you don't have to choose up front: the console follows what you run, and you can go back and forth in the same session. Each language keeps its draft in its own tab.

  • Ctrl+R or F5 in a .py file show the Python console in place of the R one. The first time, they start it: IPython with uv run --with ipython in the project folder, so it uses the project's environment (its .venv and its packages) without adding IPython to it. Next to IPython come cloudpickle, for checkpoints, pyarrow, so View() saves pandas tables as parquet, and duckdb, for SQL; a version your project pins wins. If the folder isn't a uv project, uv uses the .venv it finds; without one, Corral asks uv for a Python uv manages, downloaded the first time, rather than the system's: a system Python carries what the distribution installed in it (Ubuntu's numpy 1, for example), and the console's pyarrow, built for numpy 2, couldn't be imported. Your own UV_PYTHON_PREFERENCE wins.
  • Ctrl+R or F5 in a .R file go back to R. ctrl+b y switches by hand.
  • The console you don't see keeps running in the "corral (hidden)" tab, with its variables. If you go to that tab, you can use it there as well.
  • The variables pane, Mirador and View() follow the console in view. The pane's header says which one, for example "R 4.6.1" or "Python 3.14.3".

The first start can take a few seconds while uv prepares the environment. Python needs uv. matplotlib figures go to Mirador (see Python figures), and View(df) opens pandas, polars or pyarrow tables.

Another Python command

To start the Python console with another command, for example with more packages:

$ corral config python_console 'uv run --with ipython --with cloudpickle --with pyarrow --with duckdb --with polars ipython --no-banner -i ~/.local/share/corral-term/py/startup.py'

Keep -i …/py/startup.py at the end: that file switches Corral on inside IPython. Your command replaces Corral's whole, so keep cloudpickle, pyarrow and duckdb in it: without them there are no checkpoints, pandas tables open slower in View(), and SQL doesn't run.

Projects with renv

In a project with renv, R reads the project's .Rprofile (where renv switches on its library) instead of yours, and renv's library hides your R library, where Corral's packages are. Corral's consoles handle both: R reads Corral's profile, r/profile.R, which reads the profile R would have read (the project's, else ~/.Rprofile, or the one you set in R_PROFILE_USER) and then loads Corral. Corral then loads jsonlite, httpgd, nanoparquet and duckdb from the project's library when it has them, and from yours when it doesn't, without adding yours to .libPaths(): the project keeps its own library and its versions. A package the project brings wins over yours.

Choose the R or Python version

If you have several versions of R installed with rig, or several Pythons with uv, you can choose which one the consoles run without leaving Corral. In the palette (ctrl+b space), "Console: R version (rig)" and "Console: Python version (uv)" open a window with the versions you have installed. Enter uses the one you pick. If that console is open, Corral asks whether to restart it now, which loses its objects, or later.

R, with rig

The window lists what rig list shows. Corral runs that version's own R in its consoles, in the editor's language server and in corral doctor. rig's default stays as it is, so RStudio and your other terminals don't change. "rig's default" goes back to the R on your PATH. If the version you pick doesn't have httpgd or jsonlite, the window says so, with the command to install them in it.

Python, with uv

The window lists the Pythons uv has installed (uv python list --only-installed), one per minor version. Inside a uv project (a folder with a pyproject.toml), your choice goes to the project's .python-version through uv python pin, so uv run in a terminal uses the same Python. uv then rebuilds the project's .venv with it, and refuses a version outside the project's requires-python. Outside a project, Corral starts the console with uv run --python.

The same from a terminal, or for an agent (--json):

$ corral versions r --list
$ corral versions r 4.5.2 --restart
$ corral versions python 3.13
$ corral versions python default

Or directly with rig and uv

The window is a shortcut, so you can do it where you work. rig and uv do the same on their own:

  • rig default 4.5 changes the default R for the whole system; in rig's admin mode it asks for sudo. R-4.5 starts that version once. When you haven't chosen a version in Corral, Corral follows rig's default.
  • uv python pin 3.13 in the project, or uv run --python 3.13 for one command. Corral's console follows the project's .python-version.

Use any pane as the console

In a pane where R or IPython runs, ctrl+b m marks it as the console and, if R or IPython is already open there, switches Corral on in it. It picks R or Python by what runs in the pane.

$ corral console
$ corral console --lang python

corral console does the same; --lang r|python sets the language and --pane names another pane. In R, you can also switch Corral on with corral_activate().

The Python console needs IPython: ctrl+b m on a python without IPython marks the pane, but doesn't switch Corral on.

Restart a console

If you quit the console with q() or exit(), its pane is left with a shell. The next Ctrl+R, F5, ctrl+b y or corral eval starts the console again in the same pane. The variables pane follows the new session.

If R crashes instead (it was killed, or failed inside a package), the Ark console starts a new session by itself in the same pane and says why, in words, and what was running:

[corral] R ended unexpectedly: the system ran out of memory (signal 9), while running: big <- merge(sales, events, by = "id"). Starting a new session.
[corral] Back in 0.4 s with 5 objects (sales, events, model, clean, f) and 1 package (data.table).
[corral] Not kept: con (a connection).

The cause: out of memory, when the system's count of processes it ended for lack of memory (oom_kill in /proc/vmstat, read when R started and again when it ended) went up; stopped from outside (kill -9, say) when it didn't; a crash in R or a package (signal 11); R aborted (signal 6). For an agent's request, the code is the request's own, not the call that runs it. What came back is said before anything typed meanwhile runs. The command that was running didn't finish: what it was changing is lost, and what came before it is in the checkpoint (next section). The console reads the memory count once when R starts and once when it ends, so this costs nothing while you work.

An agent whose request was running hears at once that the console ended, instead of waiting out its timeout. If R crashes again right after starting, the console stops and leaves the shell, so a broken R doesn't restart over and over.

Objects that outlive a crash

Corral keeps a checkpoint of the objects of each R and Python console. If the session ends without you closing it (R or Python crashed, or herdr or WSL closed), the next console in the same project gets them back and says which:

[corral] Restored 12 objects (sales, model, clean, …), 2 packages (dplyr, ggplot2) and 4 plots from the R that ended without being closed (2026-11-23 14:32), first in Mirador (ctrl+b f).
[corral] Not kept: con (a connection).

When it is the same console starting R again after a crash, the line says how long it took instead: "Back in 0.4 s with …".

The packages you attached in R, and the modules you imported in Python (pd too), come back first. Functions and classes you defined in the session come back as well. If you close the console yourself (q(), exit, Ctrl+D or ctrl+b shift+q), the checkpoint goes and the next console starts empty, as before.

What survives what

What happensWhat you keepWho keeps it
You close the terminal windowEverything: R, Python, the agent and Mirador keep running, with the workspace as you left it.herdr
The editor's language server drops, or the editor closesEverything. The language server only relays between the editor and the R or Python process, which keeps running with its objects and plots. Completion comes back when the editor starts the server again (close and open the file).Corral, by design
R crashesA new session by itself, about 1.2 seconds later, with the objects back (tables, models, functions, the packages you attached) and the plots you drew, the newest 30, first in Mirador.Corral (checkpoints)
Python crashesThe next time you run Python code, a new console starts with the objects back, the modules you imported and the figures you drew.Corral (checkpoints)
The herdr server stops (wsl --shutdown, a Windows restart)herdr restores the panes; the next console in the project gets the objects and plots back from the checkpoint, for up to a week.herdr and Corral

The plots come back too. Each console keeps the newest 30 it drew in its checkpoint, as images, and the next console in the project shows them first, in Mirador and in the terminal's viewer, before its own:

[corral] Back in 0.4 s with 3 objects (sales, model, p) and 4 plots, first in Mirador (ctrl+b f).

They come back as pictures: to change one, draw it again. A plot you kept in a variable (a ggplot in p, say) also comes back as an object, and draws again: killing R with kill -9, R was back in 0.9 seconds with p, a model and the rest, and print(p) drew it. An R plot whose SVG is over 20 MB, a scatter of more than about 200,000 points, is left out, and a plot you remove in Mirador doesn't come back.

You don't notice it while you work. After a command that changed an object, a copy of the process writes what changed while you keep going; the prompt only waits for the copy to start, 2 to 7 ms in R and under half a millisecond in Python. A command that changes nothing costs about 0.3 ms. Once a minute the copy also looks at every object, for changes made in place, and still writes only what changed. R's plots are written by one small process per session, which asks httpgd for each new plot as Mirador does: a command that draws waits about 0.1 ms more, and the process uses about 1 MB and next to no CPU while you don't draw. Python's figures are already images, and the copy writes them. Performance has the measurements.

What can't come back: connections (to a database or a file) and objects that live outside R or Python, like some models; they show as "Not kept". Objects over 1024 MB in memory aren't kept either: corral config checkpoint_max_mb 4096 raises the limit. A command that crashes R loses what it was changing; what came before it is kept.

The checkpoint is a copy of your data on disk, in ~/.local/state/corral/checkpoints/, which only you can open. It lasts until the console closes, until it comes back, or a week. "Console: don't keep checkpoints of the objects and plots" in the palette, or corral config checkpoints off, turns it off.

After a restart of the Ark console, the editor's completion reconnects when Fresh starts the language server again: close and open the file, or restart Fresh.

Help in the browser

With Ark, ?mean or help(mean) open the help page in a browser window. Corral opens it with corral open, so it uses the same browser as Mirador (see CORRAL_BROWSER).
