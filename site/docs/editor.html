The script editor

The script pane is Fresh, a terminal editor without modes, with VS Code's shortcuts, menus and mouse. Corral adds running code in the console, a temporary draft, completion from your live R session and formatting on save.

Run code

  • Ctrl+R (or Ctrl+Enter) runs the selection or, without one, the whole statement under the cursor, including |> or + chains over several lines, and moves to the next statement.
  • F5 (or Ctrl+Shift+Enter) runs the whole file with source(echo = TRUE).
  • Ctrl+L inserts <- and Ctrl+U inserts |>.
  • In a .sql file, Ctrl+R runs the statement under the cursor, up to its ;, and F5 the whole file, as SQL in the console in view (SQL).

The file decides the console: code from a .R file goes to R and code from a .py file goes to Python, which comes into view (and starts, the first time). Keyboard shortcuts lists every key.

In Python

Ctrl+R sends the whole statement under the cursor: a function with all its body (blank lines included), an if with its else, a call spread over several lines, or a function with its decorators. The code reaches IPython as one pasted block and shows up at In [n]:. A selection is sent without its common indentation. F5 runs the file with %run -i, which leaves the variables in the session. Ctrl+L and Ctrl+U do nothing in a .py file.

From any pane

Select text with the mouse in any pane, for example code your agent wrote; herdr copies it on its own. Then press ctrl+b enter to run it in the console in view. Without a selection, it sends what is in the clipboard.

The draft

Each layout opens a new, empty draft, ready to use: draft.R, or draft.py when Corral starts with Python. It is temporary: if you don't save it, it is deleted when you close Corral. A session can go back and forth between R and Python, and each language gets its own draft: when you switch the console (ctrl+b y), the other language's draft opens in a second tab, and switching back shows the first again. Both are temporary and go away together. They live inside the project, in .corral/<workspace>-<date>/. Being in the project means Air, lintr and the language server use the project's configuration (air.toml, .lintr, DESCRIPTION, renv.lock).

Corral creates .corral/.gitignore with *, so git doesn't see those files and you don't have to touch your .gitignore. The file explorer doesn't show .corral/ because its name starts with a dot.

The draft is deleted when you close the editor, its pane or the layout. If something closes the editor abruptly, the abandoned draft is deleted the next time you open a layout in that project. A file you saved by hand in the draft's folder is kept, and that folder is deleted after two days.

If you open the layout in your home folder, or in a folder you can't write to, the draft goes to $XDG_RUNTIME_DIR/corral/drafts/, which WSL empties when it restarts.

The draft is a real file, and not an "untitled" buffer, because completion only works in saved files. New untitled files open as R, without completion until you save them.

Save your work

The draft is lost when the layout closes, unless you save it:

  • Ctrl+S in the draft asks for a name and saves the file in the project (the folder where you opened the layout). You can type analysis/model or a full path. Without an extension it adds .R, and if the file exists it asks before replacing it. From then on the editor works on the new file. In any other file, Ctrl+S saves as usual.
  • "Save as" in the File menu starts in the draft's folder, which can't be changed. If you save there under another name, Corral moves the file into the project with that name. If the project already has a file with that name, Corral leaves yours in the draft's folder and tells you.
  • Or ask your agent. It uses corral script --save path.R, which also saves what you haven't saved yet.
$ corral script --read
$ corral script --save analysis/model.R

--read prints the current draft, unsaved edits included. --save refuses to replace an existing file unless you add --force.

Completion and diagnostics

Completion appears in a menu while you type. You also get help when you hover over a function, its signature when you open the parenthesis, and go to definition. Diagnostics show only real problems: style is never flagged, because the formatter fixes it when you save.

R with Ark

With Ark as the console (the default), the same R as your console gives the completion, so it knows your session: cars_df$ offers the columns of your cars_df. The diagnostics are Ark's, mostly syntax errors.

Plain R

With plain R as the console, completion comes from the languageserver package, which only sees the text of your files. The diagnostics are lintr's correctness rules (an object that doesn't exist, x == NA, a repeated argument), or the project's .lintr if it has one.

Fresh starts the server with corral _lsp, which picks Ark's or languageserver according to the console.

Python

Completion, help and go to definition come from ty, which reads the project's .venv and so knows your packages. ty can check types too, but Corral turns those diagnostics off so they don't repeat Ruff's. The diagnostics are Ruff's, with its default rules: real errors such as undefined names, unused imports and syntax errors. If the project has a Ruff configuration in pyproject.toml or ruff.toml, Ruff uses it.

ty is still a 0.0 version. If something fails, go back to python-lsp-server; the change applies when the editor opens again:

$ corral config python_lsp pylsp
$ corral config python_lsp ty

The project folder

The language server reads every R file in the project folder. Fresh finds that folder by going up from the open file until it finds .corral, .git, DESCRIPTION, renv.lock or another marker.

Formatting and indentation

  • Indentation while you type, the way Air leaves it: one level inside an open parenthesis, one level for the lines that follow |>, %>%, + or another operator, and back to the margin when the statement ends.
  • Formatting with Air every time you save (Ctrl+S). In Python, Ruff formats on save the same way.

Reopen the editor after a change

Each editor reads its configuration and plugins when it opens. If you change Fresh's config.json or Corral's plugin, close the editor with Ctrl+Q (save the draft first if you need it) and open the layout again with ctrl+b a. The same goes for a shortcut you change with corral keys --change.

Corral's editor settings are in fresh/config.json and its plugin in fresh/plugins/corral.ts, in Corral's folder. Fresh comes with update checks and telemetry turned off (check_for_updates: false). Corral also turns off the Fresh plugins it doesn't use, such as agent orchestration (herdr does that already), welcome screens, Kubernetes, devcontainers, and languages like C# or C++.

Agents in the draft

Your agent can read your draft and put code into it. The text goes at the end, on a new line, as one edit you can undo with Ctrl+Z, and your unsaved work stays:

$ echo 'overview <- summary(cars_df)' | corral script --write

--write reads the text from stdin, or from a file you name. With --replace, it replaces the whole draft. The editor doesn't let other programs change a buffer you haven't saved, so Corral leaves the request next to the draft and its editor plugin applies it.

Corral's skill tells agents to replace the draft only when you ask, and never to save it on its own: the draft is temporary on purpose. See Working with agents.
